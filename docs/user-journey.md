# rpy-tool 用户旅程梳理

本文从用户完成一次 Ren'Py 写后校对 / 审阅 / 修改 / 立绘查分的路径来组织项目，而不是从代码模块出发。对应实现入口可回看 `src/App.tsx`、`src/services/tour-guide.ts` 和 `src/components/views/*`。

## 目标用户与使用场景

目标用户通常已经有一个可运行的 Ren'Py 项目，并且脚本编写进入写后阶段。用户希望在不搭后端、不上传项目文件的前提下，快速完成以下工作：

- 找到所有可编辑对白、旁白、选项行。
- 跨文件校对文本，记录通过、需修改、忽略和备注。
- 对单行文本做小修，并安全写回原 `.rpy` 文件。
- 查看角色、章节、图片、音频资源之间的引用关系。
- 按用户自己的目录规则重新分类资源。
- 给已有对白快速套用角色立绘差分。

## 旅程总览

| 阶段            | 用户目标                     | 主要入口                       | 成功信号                                |
| --------------- | ---------------------------- | ------------------------------ | --------------------------------------- |
| 0. 使用前准备   | 确保直接写文件可回退         | 关于页 / 引导说明              | 用户知道应先纳入 Git 或其他版本管理     |
| 1. 打开工作区   | 授权读取本地项目             | 顶栏「打开工作区」             | 首页出现文件、行、角色、资源统计        |
| 2. 建立项目心智 | 判断项目是否可被工具理解     | 首页统计 / 项目健康 / 诊断     | `.rpy`、章节、资源、诊断数量清晰        |
| 3. 校准资产规则 | 让资源分类符合项目目录       | 资产管理 → 路径规则            | 图片 / 音频按规则归类，命中和生效数可见 |
| 4. 文本 Review  | 批量校对脚本文本             | 文本 Review                    | 状态、备注、筛选、导入导出可完成交接    |
| 5. 就地修改文本 | 对问题行做小范围修订         | Review / Visual 底部修改栏     | 单行保存或提交全部草稿后增量重扫        |
| 6. 立绘查分     | 给对白套用已有 image 状态    | 立绘快插                       | 点击立绘后对白头部被改写并写回          |
| 7. 备用源码编辑 | 处理结构化编辑覆盖不了的情况 | 可视化编辑器 → 源文件 (Monaco) | 源文件保存后索引同步刷新                |
| 8. 复查与关闭   | 确认没有遗漏和未保存内容     | 状态栏 / 首页 / 顶栏关闭       | 无草稿，诊断可解释，工作区可安全关闭    |

## 关键用户路径

### 0. 使用前准备

用户第一次进入时，工具通过 Tour Guide 和关于页说明两件事：本地离线处理、会直接写回脚本文件。这个阶段的产品目标不是展示功能大全，而是建立安全预期：建议先把 Ren'Py 项目纳入版本管理。

实现上由 `tourGuideSteps.intro` 和 `about-view.tsx` 承担。这个步骤不要求工作区存在。

### 1. 打开工作区

用户点击顶栏「打开工作区」，选择 `game` 目录或项目根目录。浏览器弹出 File System Access API 授权后，应用会把目录句柄存入 IndexedDB，后续启动时尝试恢复。

实现路径：

- `openWorkspace()` 请求目录权限并保存句柄。
- `scanWorkspace()` 遍历文件，跳过 `.git`、`.renpy`、`node_modules`、`dist` 等目录。
- `buildRpyIndex()` 解析 `.rpy` 文件，建立行、角色、资源、章节、诊断索引。
- `AppShell.applySnapshot()` 套用资产规则、角色覆盖和章节覆盖。

用户看到的成功信号是首页统计、状态栏文件数、当前文件路径和可进入的工作流视图。

### 2. 建立项目心智

首页只承担三个任务：数据统计、项目健康、诊断。它不是营销页，也不承担完整工作流说明。用户打开项目后先看这里，判断工具是否正确理解项目：

- 是否扫到 `.rpy` 文件。
- 是否识别出 label / 章节。
- 是否识别出角色和 image 状态。
- 是否存在缺失 label、缺失资源、大图提示等诊断。

诊断项可跳转到 Visual 或 Assets，帮助用户从概览进入具体修复位置。

### 3. 校准资产规则

不同 Ren'Py 项目的图片 / 音频目录差异很大，因此资产管理不是只靠内置启发式。用户可以在资产管理顶部打开「路径规则」弹窗，按 glob 规则设置分类。

用户路径：

1. 进入资产管理。
2. 打开路径规则。
3. 从右侧目录列表选择资源目录。
4. 工具生成 `目录/**/*`。
5. 用户调整分类、优先级和启用状态。
6. 规则即时显示「命中」和「生效」数量。

实现上，规则由 `AssetPathRule` 表示，`matchAssetCategory()` 按优先级 first-match 决定分类。规则保存到 `localStorage`，并通过 `reclassifyAssets()` 重新应用到当前 snapshot。

### 4. 文本 Review

Review 是项目的核心写后流程。用户面对的是校对队列，而不是文件树。

用户可以：

- 按全部、未校对、需修改、已通过、有草稿、有备注、有诊断等范围筛选。
- 按章节和角色收窄队列。
- 搜索当前队列内的路径、行号、角色、正文。
- 使用 J / K 移动行。
- 使用 1 / 2 / 3 / 0 标记通过、需修改、忽略、重置。
- 使用 Shift / Ctrl / Cmd 多选并批量标记。
- 写备注或修改意见。
- 导入 / 导出 review JSON 做交接。

搜索在这里不是过滤。队列由筛选决定，搜索只负责命中导航和高亮，这让用户不会因为搜索词临时丢失当前校对上下文。

导出的 review JSON 会携带工作区 fingerprint。导入时如果 fingerprint 与当前工作区不一致，工具会先提示用户确认，避免把 `filePath:lineNumber` 记录误合并到错误项目。

### 5. 就地修改文本

当校对中发现小问题，用户可以直接在底部修改栏编辑当前行文本，也可以切换说话人，让对白和旁白互转。保存路径分两类：

- 单行保存：只写回当前行，并增量重扫该文件。
- 提交全部草稿：按文件分组批量写回草稿，再增量重扫涉及文件。

插入 / 删除会改变后续行号，因此工具会先提示并清除同文件草稿和 review marks，避免旧行号写回到错误内容。若同文件 Monaco 源文件草稿未保存，结构化插入 / 删除会被阻止。

### 6. 立绘查分

立绘快插不是资源浏览器，而是“给当前对白套用已有 image 差分”的高频工作流。

用户路径：

1. 在左侧按章节、角色、对白、有草稿等筛选可编辑行。
2. 在中栏选中对白。
3. 右侧展示当前角色所有 image 状态。
4. 点击一个状态。
5. 工具把 `e "文本"` 改成 `e happy "文本"` 这类对白头部。

它不会插入 `show`，也不会改正文。若当前行有文本草稿，套用立绘时会一并写回并清除该草稿。

右侧立绘区提供“点击立绘立即写回 / 点击立绘只预览”的模式切换。高频查分时保持单击写回，需要谨慎确认时可先预览，再手动应用当前选中差分。

### 7. 备用源码编辑

VisualView 的主定位是结构化行编辑。右侧传统 SpritePicker 暂停展示后，Visual 更像“文件索引 + 行列表 + 底部修改栏”的备用编辑器。

当用户需要处理结构化编辑无法表达的情况，可以切到「源文件 (Monaco)」：

- `.rpy` 使用内置 Ren'Py Monarch 语法高亮。
- `.py` 使用 Python。
- 其他文本文件按扩展名猜测 language。
- 保存前检查外部修改，避免无提示覆盖。

### 8. 复查与关闭

用户完成一轮工作后，状态栏和首页提供收尾信息：

- 草稿数量是否为 0。
- 诊断数量是否已经解释或处理。
- 当前选中行、选中立绘和文件路径是否清楚。
- 关闭工作区前若有未保存内容，会触发确认。

## 视图职责

| 视图         | 用户视角职责                     | 不承担                       |
| ------------ | -------------------------------- | ---------------------------- |
| 首页         | 概览项目状态和诊断               | 不做完整教程，不做工作流旅程 |
| 可视化编辑器 | 文件级结构化编辑和源码备用编辑   | 暂不承担右侧立绘候选         |
| 文本 Review  | 写后校对、备注、状态和交接       | 不做资源管理                 |
| 立绘快插     | 给对白套用角色 image 状态        | 不插入 show / scene          |
| 资产管理     | 角色、章节、图片、音频和路径规则 | 不作为文本校对队列           |
| 关于         | 设置入口、项目说明、重新打开引导 | 不做数据诊断                 |

## 设计约束对用户体验的影响

- 本地离线：用户无需上传项目，但必须使用支持 File System Access API 的 Chrome / Edge。
- 行级正则：速度轻、实现简单，但不覆盖完整 Ren'Py AST。产品表达应避免承诺“理解所有语法”。
- 增量重扫：保存体验更快，但跨文件关系仍由重新构建索引统一计算。
- 草稿按行号定位：插入 / 删除必须清理同文件草稿，安全优先。
- 图片保持原比例：所有角色和资源预览都应 `object-contain`，避免误导用户判断差分。
- 搜索导航：Review / Sprite / 文件索引搜索不改变列表数据源，减少上下文丢失。

## 后续评估问题

- 用户第一次打开项目后，是否能理解应该先从 Review 还是 Assets 开始。
- 缺失资源诊断是否能直接告诉用户“脚本路径”和“实际文件路径”的差异。
- 最近工作区遇到同名项目时，是否需要允许用户为目录设置本地别名。
- Monaco 源文件编辑是否需要显示同文件结构化草稿列表，提醒用户先提交或放弃草稿。
